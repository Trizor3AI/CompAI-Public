# Island Index and export-menu cowrie evidence

This reader prefers the two displayed balances in the visible, ready `MJIHud` (Islekeep's Index) owned by `AgentId.MJIHud`. Its fallback observes the initialized, visible `MJIDisposeShop` owned by `AgentMJIDisposeShop`. It does not read `CurrencyManager.ContentItemBucket`, daily upkeep, Island rank/experience/resources, export vectors, account state or private text. It performs no menu action, export, packet request or polling. Caller permissions, character/session invalidation and retention remain separate integration responsibilities.

Primary implementation evidence for the Index mapping, checked on 2026-10-26:

- [ECommons MJIHud](https://github.com/NightmareXIV/ECommons/blob/00693e92b52d067250f1724e362b5e88e3fdf365/ECommons/UIHelpers/AddonMasterImplementations/MJIHud.cs) explicitly names `AtkValues[14].UInt` as `IslandersCowrie` and `AtkValues[17].UInt` as `SeafarersCowrie`. The same source names rank/experience at different indices. Only the two named cowrie indices are used here; no button actions or other UI fields are used.
- [Explorers-Icebox's consumer](https://github.com/LeontopodiumNivale14/Explorers-Icebox/blob/a71380ec2660125bff9ab6c0df3465dcef56bef7/ExplorersIcebox/Ui/DebugWindowTabs/EcomsTestingDebug.cs) obtains addon `MJIHud`, requires `IsAddonReady`, and displays those named ECommons properties. This corroborates the addon/property association, not independent game freshness or an alternate layout discovery.

Read-only PE metadata inspection of the installed API15 `FFXIVClientStructs.dll` independently confirmed AgentMJIDisposeShop.Data at0x28; nested AgentData currency icons/counts/limits/IDs at0x08/0x10/0x18/0x20; initialization at0x28; DataInitialized at0x168; generated fixed-array getters; and inherited agent ownership/readiness methods. It also confirmed `AgentId.MJIHud`, `AtkUnitBase.AtkValues` at0x178, `AtkValuesCount` at0x1E2, `Id` at0x1E4, and `AtkValue.Type`/integral union fields. These checks verify installed typed APIs, not the semantic meaning of Index slots; that mapping comes from ECommons. Installed PDB is Windows MSF, so no portable-PDB source extraction was claimed. Production reads typed fields rather than hardcoded offsets.

Both sources require a loaded player with nonzero content ID, current AgentModule and RaptureAtkUnitManager, the exact active/ready/shown agent, and the exact visible/ready owned addon with matching native and Dalamud handle identity. The Index additionally requires a stable nonnull AtkValues pointer, 18 through256 values, and nonnegative Int or UInt balances no greater than Int32.MaxValue. It copies only slots14 and17, including their types, twice. Neither a native cap nor native icons are claimed for this source; names and positive icons come from the local public Item definitions for37549/37550. The export fallback instead requires a stable Data pointer, state3 plus DataInitialized, both supported IDs exactly once, positive limits, nonnegative quantities within those limits and matching local Item icons/names.

Public sheet checks use RawSheet/GameData/language identity. Native owners are re-resolved before dereferencing after public sheet work and before both sample copies. Complete detached samples, source kind, owners and definitions must remain stable. No AddonDirty interpretation or CanEditIsland requirement is introduced. Failure of either source never becomes a zero balance; the fallback must pass its own full checks.

The output contains only a capture timestamp and immutable Seafarer/Islander records with item ID, localized public name and quantity. Native addresses, content ID, readiness flags, icons and limits do not enter the observation. Retained results should retain this capture time and be labelled last observed by the caller.

Run `dotnet run --project tests/IslandCurrency.Tests/IslandCurrency.Tests.csproj`. The22 console groups use synthetic managed observations and isolated allocated Agent/Data/AtkUnitBase/AtkValue structures; they never resolve native singleton functions or access a running game. Cases cover ready/reversed/zero pairs, malformed IDs/counts/limits/icons/names, changed definitions/catalog, unloaded or changed owner components, rejection before an old native address can be copied, exact addon binding, stale Data pointers, incomplete initialization, and immutable output. Index cases additionally cover the documented143857/109584 pair, unrelated negative values that cannot become balances, integral types/overflow, pointer/count/source changes and stable type identity. The negative unrelated fields are synthetic sentinels; the fixtures do not claim to locate the actual daily-expense field.

These tests do not establish current in-game Index correspondence or server freshness. Compare both actual cowrie balances in the normally open Index (including a displayed daily upkeep amount), confirm refresh after a genuine balance change, and independently verify the integrated retained/permission behavior in game.
